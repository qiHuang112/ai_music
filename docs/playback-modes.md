# 播放模式

2026-09-26 用户要求保留三种可切换模式：顺序播放、单曲循环、随机播放。顺序播放按当前队列原顺序前进，最后一首结束后从第一首继续；只有一首时也继续循环。App 播放页和系统播控中心使用同一切换顺序：顺序播放 → 单曲循环 → 随机播放 → 顺序播放。

Android 播控中心的控制列表是收藏、上一首、播放/暂停、下一首、播放模式。播放模式是第五个自定义动作，点击后调用同一控制器切换逻辑，图标和文案反映当前模式。系统通知紧凑视图仅配置原来的三个位置；小米系统实际可见槽位由系统界面决定，需以真机展示为准。鸿蒙系统传入的 `sequence` 和 `list` 都归一为新的顺序播放，向系统发布列表循环状态。

验证：首次实现的 Flutter 测试 292/292、`flutter analyze` 0 问题、Android arm64 profile 构建及 `git diff --check` 均通过。Xiaomi 10 Pro（Android 13）的通知栏播控实际显示第五个模式按钮；点击后系统图标与动作名称依次变为单曲循环、随机播放、顺序播放。测试使用歌单“是”的缓存歌曲“我不难过”，结束时已停止播放。顺序播放自然走完整个列表的长时间真机验证未执行；`just_audio` 的 `LoopMode.all` 在列表末尾返回首曲索引。

独立 review 发现连续快速切换可让旧请求的 repeat 设置晚于新请求落地，造成界面显示随机播放但实际仍单曲循环。可控延迟测试先稳定复现，再将控制器的模式应用和队列重载后的模式恢复串行化。修复后完整 Flutter 测试 293/293、`flutter analyze --no-pub` 0 问题、`git diff --check` 通过；reviewer 独立运行两个相关测试文件 58/58，通过复核且无剩余阻断。该修复尚未重新打包安装，手机上仍是修复前的 versionCode 4103。
