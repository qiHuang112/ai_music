## Duo 三处适配：竖栏“…”、分屏播控条遮挡、展开竖持标题留白

用户反馈：① 有些竖栏本来放得下，却用“…”代替；② 左右分屏、来听在左且悬浮 Tab 在左时，播控条与 Tab 遮挡；③ 展开竖持时标题没顶上去，上方留白。

- **竖栏“…”**：两种来源。一是页面自己的“更多”菜单（播放页：加歌单／切换来源／热评／歌词），竖栏空间充足时仍收在一个“…”里；二是常驻的歌词／热评／队列放不下时被系统折叠成“…”。处理：原生壳按竖栏实测尺寸估算可放按钮数（按钮 50pt；顶部竖持 175、横持 82；Tab 组含边距 252，Tab 隐藏时 24；返回键 64；隐藏判断沿导航栈 `hidesBottomBarWhenPushed`），全是带图标、无勾选的普通菜单在放得下时展开成独立按钮（Flutter 侧菜单项 `ListTile.leading` 图标随描述上报）；常驻入口只填剩余空位，不再挤出系统“…”。旋转与竖栏出现／消失时重算。热评页的平台筛选是选择菜单，保留菜单，图标由“更多”换成筛选。试过 `verticalBarCompressionBehavior = .prefersBarItems`：Tab 栏被压成只剩当前页，已撤回。
- **分屏遮挡**：播控条左右边界改为窗口安全区与当前页安全区取大（分屏时竖栏只体现在页面安全区），并强制落在内容区内缩 12pt 之内。
- **展开竖持标题**：系统导航栏在时钟胶囊左侧的最上一行，标题却排在整块状态区下沿。原生端在导航栏横跨顶部时上报其起始 Y（`mastheadTop`），一级页 masthead 与之同行。
- 验证（仅模拟器，Debug，`xcodebuild -derivedDataPath build/ios_sim_dd`）：Duo 外屏横持首页竖栏为歌词＋热评、音乐库无“…”；播放页竖栏为返回＋加歌单／切换来源／热评／歌词，点加歌单弹面板、点热评进热评页；热评页为刷新＋筛选＋歌词＋队列。Device Hub 展开竖持：首页／音乐库标题与系统按钮、时钟同一行。分屏（来听左、设置右）：播控条起于竖栏右侧不再重叠，音乐库竖栏 4 个按钮全显示。iPhone 18 Pro 首页标题位置不变。`flutter analyze` 无问题；`duo_scaffold`／`widget`／热评／播放页测试 132 项通过。外屏竖持的标题位置改动后未复查（需折叠）。未装真机。

## 发版流程提速与按平台构建

用户问：打包在本地还是远端、只改 iPhone 为何三端都打、单端两三分钟能否优化，并要求三点都改。

- 分析（10274 那次 run）：正式包全在 GitHub 远端；发版 job 里重跑分析＋测试 159s（推送的 Check 已跑过同提交），APK 197s；Mac（194s）与 iOS（120s）要等 Android job 整个结束（约 7.5 分钟）才开始，总计约 11.7 分钟。那次改动含共享 Dart 代码，三端确有变化。
- `android-release.yml` 重构为 plan → android／macos／ios 并行 → publish：
  - plan（`tool/github_release.py plan`）：等同提交 `ci.yml` 结束并复用其结果（失败则不发；纯文档提交用最近通过的祖先）；取版本号；按自上次发版的改动选平台（只动 `ios/`／`macos/`／`android/` 打对应平台，共享代码／资源／依赖三端全打，文档／测试／工具／CI 不打），输入 `platforms` 可指定 `all` 或列表。
  - 各平台 job 只构建并校验（原有签名证书、包身份、架构、沙盒等检查保留），把包、校验和与清单作为工件交给 publish。
  - publish：重新核对工件，未构建的平台沿用上一版 Release 的更新清单（App 与局域网读到的版本不变，不会误报更新；没有 Android 清单则拒绝），建草稿、全部下载回读比对后才设为最新；同 tag 的失败草稿先删除重建。
  - Android 去掉重复测试，改用 `gradle/actions/setup-gradle`（v6.4.0）缓存，`android/gradle.properties` 开启 `org.gradle.caching`。Mac 仍为 Universal（是否改为仅 Apple 芯片未做，需用户决定）。
- 验证：`tool` 单元测试 61 项通过（新增规划／门禁／发布测试，更新 Android／Mac 测试）；用真实仓库数据只读演练：`a3bcdc4..66ee2f7` 判为三端，`66ee2f7` 之后只改文档判为无需构建，Check 门禁对 `66ee2f7` 通过，最新 Release 的三份清单可沿用。工作流尚未在 GitHub 实际运行，首次发版时验证。未推送。
