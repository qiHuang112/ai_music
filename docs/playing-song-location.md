# 正在播放歌曲的列表定位

2026-10-19用户要求：当前歌曲属于打开的歌单时，直接定位到该歌曲；从播控中心打开“当前队列”时，也直接定位到当前歌曲。

- 每次打开歌单或队列时定位一次，歌曲出现在可见区域；之后允许自由滚动，播放进度、歌词、封面更新以及自动切歌不把用户拉回。
- 覆盖自己的歌单、收藏、榜单和搜索来源歌单。使用歌曲记录或来源歌曲身份匹配，避免同名不同歌手、不同版本误定位；来源音频切换后仍能定位原歌单里的歌曲。
- 长列表保持懒加载，兼容靠后曲目、大字体、不同高度的行以及折叠标题。没有当前曲或不属于该列表时按原样打开；加载后再定位，不因异步数据到达漏掉。
- 实测场景：靠后的歌曲打开歌单／队列、退出重开、手动滚走后收到播放器更新、无匹配、列表异步加载以及切换音源。

2026-10-20追加：定位当前歌曲需要短滚动动画。歌单／当前队列统一260毫秒easeOutCubic，页面进入后再播放；长列表先准备目标附近的一屏内容，再滚入当前歌曲，避免展示中间定位过程。用户手动拖动即接管，后续更新不重播；系统关闭动画时立即定位。

已交付体验10261并装77自测：150首自建歌单／队列Always Online首曲、前轮同组件黑武士非首曲及重开、59首来源歌单散场夏天／春不晚及播放中打开队列均可见。自动覆盖1000首变高行中／末尾、超长页头第0首、异步加载、无匹配、自由浏览和重开；旧第0首跳过定位回归先失败后通过。见[当日记录](worklog/2026-10-19.md)。

2026-11-09用户反馈（最新包）：① 播放列表里点正在播放的那首，应像点播控条一样直接打开播放页，不必返回首页再点播控（各列表的共性问题）；② 从歌单点进列表（当前歌曲在该歌单里）跳转时仍卡顿。
- ①：歌单／收藏／榜单行、当前队列、在线歌单预览、下载页、搜索里的本地歌曲、听歌记录，点当前歌曲（暂停中也算）打开播放页，不重新播放；队列是底部面板时先收起再打开；已在播放页（宽屏播放页里嵌的队列、或从播放页打开的队列）不再叠一层。Mac 保持原行为。“播放全部”按钮不受影响。
- ②：卡顿来自打开时定位：普通列表跳到第 N 首要在一帧里构建并排版前面全部行（离屏实验：定位第 250 首一帧建 251 行），且正好发生在页面滑入期间；另外打开歌单会记录使用次数并通知全应用重建。手机端歌单行改为统一行高（副标题与“需核对”同一行），列表按行高直接定位，同样场景一帧只建约 16 行；记录使用次数推迟到页面滑入完成后。
