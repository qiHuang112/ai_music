# 截图导入歌单与下一首预下载

状态：用户已确认，待开发实现。唯一工程为当前 Flutter LAN 版 main。

## 入口与识别

- 搜索框最右侧增加图片图标，进入截图导入页；支持多选图片、预览、删除及调整顺序。
- 按图片和歌曲行顺序识别歌名、歌手、版本信息，过滤按钮、广告等非歌曲内容。
- 重叠截图中的同一歌曲去重，保留首次顺序；不同版本不能盲目合并。
- 保留识别信息与来源图片的关联，允许用户修改识别结果并重新搜索；无法确定的字段不编造。
- OCR 技术尚未选定。开发先检查项目与平台能力，优先评估端侧识别；不得未经明确授权将截图发送给外部云服务。
- 用户已准备本地样例，但尚未提供路径。先做可独立推进的实现与测试，拿到样例再实测，不扫描无关私人目录。

## 匹配与选择

- 每首识别歌曲为一组，搜索匹配时结合歌名、真实歌手、版本和完整音频可用性。
- 默认简洁模式展示每组首选项，可信且通过完整音频校验的首项默认选中，并提供“一键选择推荐项”。
- 切换详细选择模式后每组展示前三个候选，组内单选；允许取消整组。
- 每组可展开更多结果（第一版最多 10 项）并收起，保持已选项；不足数量不凑数。
- 低置信、错误艺人、翻唱/Live/伴奏版本冲突不能自动选中；未匹配组保留供修正/重试。
- PREVIEW、网盘、HTML、防护页和不完整媒体不能作为可下载歌曲。
- 按现有 resolver 实际能力实现，不假设历史 Native 多源实现存在；源站问题仅影响对应候选。
- 搜索限速、去重、缓存并限制并发；不得为展开/收起重复请求同一批结果，不进行无限重试。

## 加入歌单与下载

- 底部显示已选歌曲数量，可添加到已有歌单或新建歌单。
- 默认“添加到歌单”：持久化所选版本、稳定来源标识与元数据，暂不强制下载；过期媒体地址在播放时刷新。
- 另提供“添加并下载”，按队列处理；已有有效本地音频复用。
- 保持现有 LAN 同步、文件夹歌单、缓存和本地播放兼容，不为新功能迁移整个架构。
- 失败逐首记录，可重试；不删除歌单条目、不影响其他成功歌曲。

## 播放与梯度重试

- 当前歌曲播放时按需下载，命中有效本地缓存则直接播放。
- 当前歌曲稳定播放后立即预下载下一首，一次只提前准备一首；同一首只允许一个下载任务。
- 网络中断/超时/临时服务器错误：失败后依次等待 5、15、30、60 秒，再以至少 60 秒间隔重试，附小幅随机延迟；重试不得早于下限。
- 预下载失败一次不立即跳过，当前歌播放期间持续按上述节奏准备下一首。
- 链接过期时重新解析后重试；明确无资源、非音频、错误歌曲不反复下载，标记后继续准备后面的可用歌曲。
- 429 或源站退避要求优先，等待时间不短于源站要求；断网时停止定时请求，恢复后去重触发一次尝试。
- 支持续传的来源可保留有效下载部分，但必须校验版本/媒体一致性，不能拼接不同内容。
- 切歌、换歌单、重排队列或销毁会话时取消过期安排，防止旧任务回调污染新队列。
- 当前歌曲结束后，下一首未就绪最多再缓冲 3 秒；仍不可播才跳过，转向后续可用歌曲。避免全歌单失败时循环空转。
- 失败歌曲不永久失效，下次轮到仍可重新尝试；整体断网时优先本地可用歌曲。
- 失败/取消不产生正式成功缓存，完成校验后再转正，歌词/封面与真实歌曲关联保持一致。
