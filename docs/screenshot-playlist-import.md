# 截图导入歌单与下一首预下载

状态：2026-09-26 的简化截图流程已构建并安装体验包，待用户真实相册验收。唯一工程为当前 Flutter LAN 版 main。下文 2026-09-25 的严格匹配及真机记录是历史方案，不代表当前方案已验收。

## 入口与识别

- 搜索框最右侧增加图片图标，直接打开系统相册选择器；支持多选图片、预览、删除及调整顺序。
- 按图片和歌曲行顺序识别歌名、歌手、版本信息，过滤按钮、广告等非歌曲内容。
- 重叠截图中的同一歌曲去重，保留首次顺序；不同版本不能盲目合并。
- 保留识别信息与来源图片的关联，允许用户修改识别结果并重新搜索；无法确定的字段不编造。
- OCR 使用端侧识别，不将截图发送给外部云服务。
- 当前 Android 使用本机 ML Kit 中文模型，iOS 使用本机 Vision；不上传截图。实现参考了 Google 的 [ML Kit 示例](https://github.com/googlesamples/mlkit)，并评估了 [Tesseract OCR](https://github.com/tesseract-ocr/tesseract)，但未引入额外 OCR 服务。HarmonyOS 尚无此 OCR 桥接，不能声称该平台已支持。
- 用户截图在手机相册中；仅通过系统图片选择器处理用户选中的截图，不扫描无关私人目录。

## 匹配与选择

- 每首 OCR 歌曲按歌名发起有界在线搜索；接口首批有结果就使用原始返回数量和顺序，不等待凑足 10 首，不逐首解析/探测完整音频。主源无结果才查备用浅页。
- OCR 有歌手时优先默认选择返回列表中歌手一致的候选；否则默认选第一首。没有识别出歌手也选第一首，不因低置信或缺歌手制造大量“待修正”项。
- 搜索到的歌曲默认全部勾选。用户可取消、展开当前已取得的候选改选，或修改 OCR 文本后仅重搜这一首；展开与勾选不二次请求。全部搜索结束前不开放批量下载。
- 截图匹配阶段不验证歌曲是否完整、不要求严格同曲身份；实际下载仍保留文件类型、内容与正式缓存安全门禁，下载失败逐首呈现，不污染正式缓存。
- 按现有 resolver 实际能力实现，不假设历史 Native 多源实现存在；源站问题仅影响对应候选。
- 搜索按源限速、同词请求合并并复用本轮结果，不为展开/收起重复请求，不进行无限重试；源站保护或连续故障应及时停止后续批次。

## 加入歌单与下载

- 底部显示已选歌曲数量，可添加到已有歌单或新建歌单。
- 可选“加入歌单”：持久化所选版本、稳定来源标识与元数据，暂不强制下载；过期媒体地址在播放时刷新。
- 主按钮“下载已选”直接按当前勾选结果顺序下载，不要求先挑歌单；“加入歌单”保留为可选操作。已有有效本地音频复用；截图入口不强制严格同曲身份比较。
- 下载完成后歌曲删留完全由用户自行决定，不属于截图识别、匹配、下载流程，也不是本功能验收阻塞点。
- 保持现有 LAN 同步、文件夹歌单、缓存和本地播放兼容，不为新功能迁移整个架构。
- 失败逐首记录，可重试；不删除歌单条目、不影响其他成功歌曲。

## 播放与梯度重试

- 当前歌曲播放时按需下载，命中有效本地缓存则直接播放。
- 当前歌曲稳定播放后立即预下载下一首，一次只提前准备一首；同一首只允许一个下载任务。
- 网络中断/超时/临时服务器错误：失败后依次等待 5、15、30、60 秒，再以至少 60 秒间隔重试，附小幅随机延迟；重试不得早于下限。
- 预下载失败一次不立即跳过，当前歌播放期间持续按上述节奏准备下一首。
- 链接过期时重新解析后重试；明确无资源、非音频、错误歌曲不反复下载，标记后继续准备后面的可用歌曲。
- 429 或源站退避要求优先，等待时间不短于源站要求；断网时停止定时请求，恢复后去重触发一次尝试。
- 支持续传的来源可保留有效下载部分，但必须校验版本/媒体一致性，不能拼接不同内容。
- 切歌、换歌单、重排队列或销毁会话时取消过期安排，防止旧任务回调污染新队列。
- 当前歌曲结束后，下一首未就绪最多再缓冲 3 秒；仍不可播才跳过，转向后续可用歌曲。避免全歌单失败时循环空转。
- 失败歌曲不永久失效，下次轮到仍可重新尝试；整体断网时优先本地可用歌曲。
- 失败/取消不产生正式成功缓存，完成校验后再转正，歌词/封面与真实歌曲关联保持一致。

## 验证与交付

- 覆盖多图重叠、识别修正、搜索加载态、空态、按接口实际数量显示候选、同歌手优先/否则首条、默认全选及取消/重选、选择持久化和批量部分失败。
- 覆盖加入后不立即下载、已有文件复用、下一首预下载、退避时序、断网恢复、链接过期、限流、队列变化和无可播歌曲停止。
- 用可控时钟/假网络验证重试，不为测试反复请求真实站点；真实样例低频验证。
- 提供实际样例的识别/匹配/选择结果；截图未提供或 OCR/源站不可用时准确标出未验证项，不声称全通过。
- 开发完成后先在开发任务中交用户进行功能验收。验收前代码 review 保持待命，开发不得主动发起 review。
- 用户验收通过后，由用户亲自在代码 review 任务中发起对话，review 才开始工作。
- 后续用户在开发任务中提出的变更需记录到本文并继续实现；review 阶段的意见在用户启动 review 后处理。
