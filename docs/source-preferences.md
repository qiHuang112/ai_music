# 默认音源与全场景切换

2026-10-09：按用户最新要求，在10190热评包基础上接回本文件功能；保留回退后的播放器、歌词、设置及公共主题样式。下列既有验证记录作为参考，本轮测试与手机交付另见[当日记录](worklog/2026-10-09.md)。

2026-10-08 用户需求：默认改为 FLAC，Auto 对频繁失败来源在本次进程中降级；设置切源必须覆盖此前保存但未播放／下载的歌单歌曲。

- 新安装、缺失或损坏的源偏好默认 FLAC；已明确保存的 Auto／布谷／FLAC 保留，不修改已有用户选择。
- 设置源用于首页搜索、切换来源页初始选择、截图与歌单匹配、未缓存播放、歌单下载、收藏下载及后续预缓存。
- 旧歌单保存的自动候选若来自另一个源，或与原歌名／歌手／版本不再符合可靠匹配要求，在下次使用时重新匹配。旧导入仅有 onlineTrack、没有原始 song 元数据的条目也覆盖。
- 完整有效本地文件优先复用；局域网歌曲不走网络音源。单曲手动选择的来源仍固定，只有用户在“切换来源”页再次选择才替换。
- 切换设置会使旧搜索、尚未保存的自动候选和已准备的在线队列地址失效，旧请求晚到不能覆盖新选择。歌曲逻辑 ID、歌单归属和播放次序保持。
- 匹配候选缓存按音源模式及 Auto 可用源集合隔离；新匹配规则使用新缓存版本，避免复用以前的错误排序。当前播放不因修改设置而强制中断，之后加载按新设置执行。
- 旧缓存补齐元数据也遵循当前设置；已有音频的真实来源／平台／ID及有效标题不因补歌词、封面而被改成另一个来源。
- 在线歌单的 Auto 查询使用完整艺人及完整标题，不复用截图按标题的少量候选召回；QQ 的完整 `title` 和原始时长在导入时保留，以免伴奏、浴室／慢摇等版本在匹配前丢失。
- 旧QQ歌单原始元数据缺少版本字段时按 `metadataVersion=0` 读取。在下次播放／下载前，按原QQ数字歌曲ID读取官方详情补齐元数据，无需删单重建。收藏和全部歌单引用串行、单次原子保存；新写入的歌名／艺人／元数据版本不能被晚到旧请求覆盖。
- 完整元数据确认录音标题、版本或艺人改变时，仅取消非手选的自动音源引用，随后按当前设置重新匹配；逻辑歌曲ID、添加时间、收藏、顺序和用户手选来源保留，旧缓存实体文件不删除。仅格式、繁简、时长或封面补齐且候选与原曲无明确矛盾时保留自动来源；旧缓存即使有效，明确错核心歌名、艺人无交集或候选标注冲突版本时也解除自动引用。缺合作署名或缺版本标签属于待核对，不单凭这些缺项判错。
- 健康降级的规则见 [自动音源降级](source-health.md)。播放媒体失败达到阈值时，Auto 当前歌曲会尝试改用仍可用的来源；已有在线队列的下次请求重新准备。手动固定来源不自动替换。

## 验证场景

1. 未下载的歌单歌曲已有布谷自动候选，改 FLAC 后直接播放／下载全部／收藏，实际解析与下载均来自 FLAC。
2. 布谷匹配未完成时切 FLAC，新匹配先返回，旧布谷结果不能回写。
3. 同一队列已准备的下一首在切源后重新加载地址，首首切换与回到之前歌曲同样生效。
4. 本地完整歌曲在切源后仍直接播放；手选音源仍固定。
5. Auto 某源搜索、解析或音频传输连续故障三次后，本次应用运行不再新发起该源的自动请求，重启恢复。
6. 已经导入QQ歌单“凡人百世书-BGM／张天一／7首”（9765682818）后升级，播放／下载旧条目能补回伴奏等完整版本并使错误自动候选失效；手选来源保留，文件仍在缓存中，不要求重新创建歌单。

该实际案例修复后 FLAC／Auto 共14次真实查询，均为5首元信息高把握、2首需核对；伴奏候选缺王忻辰署名，Manestein候选缺慢摇版本标记，尚未核验音频内容。具体证据与边界见[歌曲匹配](song-matching.md)。

开发自测与交付证据见 [2026-10-08工作日志](worklog/2026-10-08.md)。
