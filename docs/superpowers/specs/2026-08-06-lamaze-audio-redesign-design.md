# 拉玛泽沉浸式引导音频重制设计

## 目标

重制现有 4 首普通话拉玛泽呼吸陪伴曲，使其首先是一套能够自然沉浸的轻音乐，其次才由低密度人声提供即时动作提示。新版不得出现报幕、产品说明式旁白、模拟吟唱或明显的程序合成音色。

本设计只调整音频制作、引导词和随附元数据，不改变 4 首曲目的稳定 ID。Flutter 客户端通过 SHA-256 识别内容更新，并继续沿用原歌曲引用、收藏和歌单关系。

## 已确认的听感方向

- 纯器乐轻音乐铺底，不含演唱、哼鸣或歌词人声。
- 主音色为柔和钢琴、温暖弦乐和极淡的空气感铺底。
- 不使用鼓点、强低音、流水、鸟鸣、白噪声或突兀铃声。
- 引导人声为成熟、稳定、亲切的普通话女声，接近经验丰富的助产士，而不是广告播音或冥想主播腔。
- 人声平均每 20 至 35 秒出现一次，每句只表达一个当下动作。
- 背景音乐使用采样乐器重新编曲，不继续使用 NumPy 正弦波音垫。

## 曲目结构

| 曲目 | 时长与速度 | 音乐结构 | 开场和人声重点 |
| --- | --- | --- | --- |
| `01-慢呼放松` | 约 5 分钟，60 BPM | 稀疏钢琴主旋律，弦乐缓慢托底，无明显高潮，首尾适合循环 | 音乐先进入约 6 秒；直接提示肩膀放松、轻柔吸气和缓慢呼气 |
| `02-宫缩浪潮` | 约 3 分钟，64 BPM | 钢琴保持稳定，弦乐做柔和的来到、增强、退去，不制造紧张感 | 只在关键位置提示呼吸流动和身体放松，不解释曲目用途 |
| `03-暂缓用力` | 约 2 分钟，72 BPM | 轻柔而清晰的钢琴音型辅助短呼吸，无打击乐 | 3 秒内进入“嘴唇轻轻张开、短短呼气”等动作；不自行下达用力指令 |
| `04-跟随医护` | 约 3 分钟，60 BPM | 四首中最稀疏，给现场医护说话留出空间 | 提示先听医护、肩膀放松和自然呼吸，不替代实时医护指令 |

所有曲目使用短淡入和无突变的尾奏。循环点不得出现截断人声、未释放音符或明显响度跳变。

## 引导词规则

音频和 LRC 只保留实际听到的动作口令。允许的句式类似：

- “肩膀松下来。”
- “轻轻吸气……慢慢呼出去。”
- “嘴唇微微张开，短短地呼气。”
- “如果头晕，先回到自然呼吸，告诉身边的医护。”

以下内容不得出现在音频或 LRC：

- “这是一段……”“这首引导……”“本曲用于……”等自我介绍或报幕。
- “你可以循环播放”“下面我们开始”等产品操作说明。
- 宫口厘米数、基于阶段的自行判断、无痛或顺产承诺。
- 长时间屏气要求，或未经医护确认的向下用力口令。

用途、安全边界和使用条件保留在 TXT、README 与 JSON 元数据中。`03-暂缓用力` 的标题、TXT 和 README 必须明确说明只在医护要求暂缓用力时使用；音频本身直接给动作提示，避免先播放长段说明。

## 制作管线

1. 将曲目定义拆成编曲规格、引导词和混音规格三个独立部分，避免文案变化迫使整套编曲重写。
2. 使用原创 MIDI 音符、和声和力度曲线驱动采样钢琴与弦乐。优先采用 MuseScore General 或同等质量、许可允许导出成品音频的采样库；素材来源、版本、许可证文本和 SHA-256 随交付记录保存。MuseScore 官方资料将 `MuseScore_General.sf3` 标为 MIT 许可，可作为首选候选。
3. 钢琴、弦乐、空气铺底和人声分别渲染为 stem，再由 FFmpeg 统一重采样、均衡、压缩、自动压低背景和母带限制。
4. 女声引擎不在设计阶段绑定到单一系统声音。实现时以普通话清晰度、自然停连、无错读和成熟女声气质为门槛筛选本机或可合法使用的声音；最终使用哪一个声音由试听样片确认。
5. 先产出约 45 秒的 `01-慢呼放松` 试听样片。用户确认音乐质感、人声、语速和音量比例后，才批量渲染 4 首完整曲目。

## 混音与文件规格

- 人声居中，背景在口令期间平滑降低约 2 至 3 dB，释放后自然恢复。
- 人声只使用轻微空间感，不添加吟唱振音、明显回声或夸张混响。
- 母带避免削波和刺耳高频，真峰值不高于 -1.5 dBTP；4 首主观响度保持一致。
- 每首交付 48 kHz WAV、192 kbps MP3、UTF-8 LRC、UTF-8 TXT 和 JSON 元数据。
- 共用原创 PNG 封面；MP3 写入标题、歌手、专辑和封面标签。
- 4 首沿用 `lamaze-slow-relax`、`lamaze-contraction-wave`、`lamaze-defer-pushing`、`lamaze-follow-care-team` 稳定 ID。

## 验收与错误处理

试听样片未获用户确认时，不批量替换 Windows 音乐库中的正式文件。完整生成阶段任一曲目失败时，保留上一版正式文件，先在临时目录完成整套验证，再原子替换交付目录。

自动检查至少覆盖：

- 曲目数量、目标时长、BPM、48 kHz 采样率和 MP3 码率。
- WAV/MP3 可解码、无削波、无异常长静音、首尾可循环。
- LRC 时间戳递增并位于曲目时长内。
- 音频/LRC 不含报幕句、禁用承诺、宫口厘米数或自行用力口令。
- JSON 稳定 ID 不变，所有交付文件 SHA-256 重新生成。

人工验收包括耳机与手机扬声器试听，重点检查背景是否干净、人声是否自然、口令是否足够短、口令间是否有 20 至 35 秒音乐空间，以及现场医护声音是否仍容易被听见。

## 部署

通过整套验收后，将新版文件放入 `E:\music\Lamaze\`。Python 局域网服务重新生成清单后，音频 SHA-256 变化会触发内容更新；稳定 ID 保证手机上的歌曲引用不变。配合文件夹歌单同步功能，4 首曲目会被增量加入同一个 `Lamaze` 自建歌单。
