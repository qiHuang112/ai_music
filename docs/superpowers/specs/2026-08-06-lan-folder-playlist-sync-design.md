# 局域网文件夹到自建歌单同步设计

## 目标

局域网音乐库中的每个“直接包含歌曲的文件夹”在 Flutter 客户端中对应一个自建歌单。同步保持安全增量语义：新增或更新歌曲并补充歌单成员，但不因为电脑端删除或移动文件而删除手机歌曲、歌单成员、收藏或歌单。

`E:\music\Lamaze\` 中的 4 首拉玛泽曲目必须在同步后进入同一个 `Lamaze` 自建歌单。

## 文件夹映射规则

- 只为直接包含受支持音频文件的文件夹建立歌单。
- 歌单显示名使用相对于音乐库根目录的 POSIX 风格路径：
  - `E:\music\Lamaze\01.mp3` → `Lamaze`
  - `E:\music\胎教\钢琴\01.mp3` → `胎教/钢琴`
  - `E:\music\胎教\古典\01.flac` → `胎教/古典`
- 根目录中的歌曲不自动创建文件夹歌单。
- 文件夹路径区分大小写的显示形式来自真实相对路径；稳定关联键使用服务器 `libraryId` 与规范化后的 `folderPath`，避免不同音乐库互相覆盖。

## API 协议

Python 标准库服务器在每个 track 对象中增加可选字符串字段 `folderPath`：

```json
{
  "id": "lamaze-slow-relax",
  "title": "慢呼放松",
  "artist": "AI Home",
  "album": "拉玛泽呼吸引导",
  "folderPath": "Lamaze",
  "audio": {}
}
```

协议仍使用 `schemaVersion: 1`。`folderPath` 是向后兼容的可选字段：旧服务器未提供时，客户端继续导入歌曲，但不为该歌曲自动建立歌单。

服务器通过音频文件父目录相对于库根目录计算 `folderPath`，不接受 JSON sidecar 覆盖该字段。输出前必须验证它不是绝对路径，不包含空段、`.`、`..`、反斜线目录穿越或 NUL 字符。根目录使用空字符串。

Flutter 模型接受空字符串或安全相对 POSIX 路径。任何不安全路径使清单解析失败，不进入下载阶段。

## 客户端数据模型

`LanTrackEntry` 增加 `folderPath`。`MusicPlaylist` 增加可选的 `lanFolderKey`，写入现有 `playlists.json`，格式由 `libraryId` 和规范化 `folderPath` 生成。旧歌单没有该字段时正常迁移。

`lanFolderKey` 只负责重复同步时找到同一个歌单，不把文件夹歌单做成新的公网搜索源或单独页面。它仍显示在当前“自建歌单”区域，并保留现有播放、排序、添加和删除歌曲能力。

## 同步流程

1. 获取并验证清单。
2. 继续使用最多两个 worker 下载歌曲、歌词和封面；先写临时文件，校验大小、SHA-256 和音频签名，再原子转正。
3. 每次成功导入、内容更新或哈希相同跳过时，记录该歌曲的本地稳定 cache ID 和 `folderPath`。
4. 所有 worker 完成后，按 `folderPath` 分组，通过一次串行歌单事务增量合并：
   - 优先按 `lanFolderKey` 查找已关联歌单。
   - 首次同步没有关联键时，复用显示名完全相同的现有自建歌单，并为它补写关联键。
   - 没有同名歌单时创建新歌单，名称为 `folderPath`。
   - 保留现有成员和顺序，只把尚未存在的新歌曲追加到末尾。
5. 保存歌单后重新载入缓存和自建歌单，使界面立即显示结果。

如果两个不同音乐库中的同一路径试图占用已经绑定到另一 `lanFolderKey` 的歌单，不复用该歌单。新歌单使用 `folderPath（局域网-<libraryId 后 6 位>）` 作为确定性名称；若该名称仍被未关联歌单占用，则从 `-2` 开始追加最小可用序号。这样两个文件夹不会共享同一关联键，重复同步也不会继续产生新歌单。

## 增量与失败语义

- 重复同步是幂等的，不重复创建歌单或添加歌曲。
- 电脑端删除、移动或重命名歌曲，不自动删除手机缓存，也不从任何歌单移除。
- 电脑端删除文件夹，不删除手机歌单。
- 手机原有歌曲、手动加入的歌曲、收藏和其他歌单始终保留。
- 单曲下载或校验失败时，该曲不参与本轮歌单新增；其他成功曲目照常导入并加入对应歌单。
- 若歌单持久化失败，已经校验通过的歌曲仍保留在缓存中；同步结果显示歌单合并失败，下一次同步可重试，不回滚或删除歌曲。
- 空清单是成功的无操作，不修改任何歌单。

## 同步结果与界面

`LanSyncResult` 在现有新增、更新、跳过和失败计数之外，增加已创建歌单数、已更新歌单数和歌单合并错误。下载管理页沿用“扫描并同步”入口，在完成摘要中显示歌曲和歌单结果，不新增自动或后台同步。

## 测试

Python `unittest` 增加：

- 直接文件夹、中文文件夹和嵌套文件夹的 `folderPath`。
- 根目录歌曲返回空 `folderPath`。
- 文件夹名与 sidecar 专辑名互不影响。
- 路径编码、安全路径和目录穿越防护。

Flutter 测试增加：

- 新旧清单兼容以及不安全 `folderPath` 拒绝。
- 首次同步创建歌单并加入歌曲。
- 同名自建歌单复用，同时保留原成员和顺序。
- 嵌套路径映射为独立歌单。
- 重复同步不重复歌单或成员。
- 内容更新保持歌曲 ID 和歌单引用。
- 部分失败只加入成功歌曲。
- 电脑端移除歌曲后，手机缓存和歌单成员仍保留。
- 空库、断网和歌单写入失败不破坏现有数据。
- `Lamaze` 文件夹中的 4 首歌曲进入同一个 `Lamaze` 歌单。

## 版本与交付

Flutter 版本升级为 `1.0.0-lan.2+2102`。实现保持 Python 服务只使用 Python 3.9 标准库，Flutter 工程不增加 Python 或服务端运行依赖。

完成 Python 与 Flutter 测试、`flutter analyze` 和 Android release 构建后，先在小米 10 Pro 验证首次同步、歌单生成、重复同步、歌词、播放和停止服务器后的离线播放。小米 17 Pro 仅在用户再次明确提供有效无线 ADB 地址并授权最终验收时操作。
