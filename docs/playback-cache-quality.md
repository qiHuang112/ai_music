# 播放缓存与下载品质（2026-09-27）

## 已确认的行为

- 设置里提供单选的默认下载品质：高、中、低，初始为高。仅主动下载单曲或点“下载全部”时使用。实际来源缺少目标品质时选择可用版本，并保留实际品质记录。
- 将歌曲加入歌单、打开歌单、识别歌单均不自动下载音频。原有进入自建歌单后 Wi-Fi 自动下载的行为取消。
- 未缓存的在线歌曲点击播放时，先按低品质解析并边下载边播放，不等完整下载。已有完整缓存时直接使用已有文件。播放产生的低品质缓存不会自动升级。
- 播放保持原音源：布谷 YY 的歌曲向布谷 YY 取可播放直链，FLAC 来源的歌曲向 FLAC 的 `getUrl` 按 MP3 128K 优先取直链。布谷 YY 的 `geturl` 没有品质参数；其 `getdown` 返回的网盘分享链接不能当音频流使用，所以该来源无法保证一定取得 128K，界面与记录必须保留实际品质。既有加密 `.mflac` 精确同曲回退另循原规则。
- 切走当前歌曲时停止下载，保留已下载的临时片段；下次播放重新解析链接并从缺失位置继续。来源不支持 HTTP Range 时重新下载。完整下载并通过校验后才作为正式缓存。
- 未完成的片段合计最多 200 MB，超过时按最近使用时间清理最旧片段。完整播放缓存不受该上限影响。
- 用户主动下载已经有低品质播放缓存的歌曲时，按设置品质升级；下载完成后未来播放优先使用主动下载的版本。主动下载不触发不必要的重复副本。
- 搜索结果的下载按钮只把主动下载视为“已下载”：仅有播放缓存时仍显示“下载”，主动下载后才显示“重新下载”。
- 设置的缓存区两行：第一行显示播放缓存占用 MB，带“清除”，只清播放产生的完整缓存和临时片段；第二行显示主动下载的歌曲数量，不带清除。清理不删除歌单、收藏、匹配结果或主动下载文件。
- 如果收藏/自建歌单引用的是待清除的播放缓存记录，清理前先把该引用转换为同源在线歌曲条目，保留歌单位置、收藏与可再次点播的身份；搜索结果直接在线播放时加入收藏也保存在线候选。

## 验收场景

1. 加入一张 33 首在线歌单后，音频缓存与下载任务数不增加；点播未缓存歌曲，开头缓冲后播放且音频仍在下载，完整后计入播放缓存。
2. 下载到一半切歌，片段仍在；再点播时支持 Range 的来源从已有字节后续传，不支持的来源从头重新下载。未完整的片段不计作已下载歌曲。
3. 主动下载单首和整张歌单按当前高/中/低设置，低播放缓存不会自动升级；主动升级完成后设置的“已下载歌曲”首数增加，清播放缓存不会删除它。
4. 临时片段超 200 MB 时优先清理最久未播放片段。清除播放缓存不影响歌单元数据或主动下载文件。
5. 播放缓存命中或开始边播边缓存时，不弹出成功提示；搜索结果点播期间显示加载状态，解析失败或开始播放后音源中断时显示失败原因。
6. 搜索结果直接点播 FLAC 来源《哎呀 / 王蓉》时，播放器能查找该在线候选及其歌词；音频尚未完整缓存时也能加载歌词。
7. 同一歌曲的两个播放分段请求重叠时，较短请求先结束并触发临时缓存清理，仍在写入的片段不会被删。服务端忽略请求上界而返回更长的 `200` 或 `206` 时，交给播放器的字节数与声明长度一致，后续请求能从已写入片段继续，或在不支持 Range 时从零重下。
8. 同一在线歌曲先有低品质播放缓存、后又主动下载高品质时，重启应用后的收藏和自建歌单指向主动下载文件；清除播放缓存仍保留主动下载版本。

## 音源调研与实现依据

- 项目已有 FLAC 解析器调用站点 `ajax.php?act=getUrl`，以 `songid/format/bitrate/time/sign` 换取音频直链；[使用同站接口的开源客户端示例](https://mykb.cipindanci.com/archive/SuperKB/4662/)也是取得 `resp.data.url` 后交给播放器。2026-09-27 在用户正常打开的站点页面核对了《日不落 - 蔡依林》的在线播放，并检查其公开的[前端脚本](https://flac.music.hi.cn/assets/index-C04zSQOO.js)：页面优先从 `minfo` 选择 MP3，通过 `getUrl` 解析直链，再把 URL 交给 APlayer；APlayer 创建原生 `audio` 元素，设置 `preload: "auto"`，直接赋值 `audio.src`，并用 `audio.buffered` 显示已缓冲进度。网页本身不实现分块下载器；按需读取和跳转时的字节请求由浏览器媒体栈负责。脚本的静态文件名可能随站点更新变化。FLAC 的[编解码器仓库](https://github.com/xiph/flac)提供文件格式/解码能力，不是该网站的前端源码。
- 项目已有布谷 YY 解析器区分 `geturl` 可播放直链与 `getdown` 网盘链接；[开源客户端的布谷 YY 实现](https://github.com/CharlesPikachu/musicdl/blob/master/musicdl/modules/thirdpartysites/buguyy.py)也分别处理网页播放 URL 与夸克网盘下载 URL。流播放只用前者。
- 是否支持续传取决于最终音频服务器，而不是上述解析站：请求 `Range`，只在实际得到匹配的 `206/Content-Range` 时拼接临时前缀；若得到 `200`，丢弃旧前缀，从零开始。单元测试覆盖边接收边吐给播放器、206 续传和 200 重下。77 真机已分别播放 FLAC 来源《Jolin / 木木》和布谷来源《Sleep / 王源》，两条实际音频直链的 CDN 均对范围请求返回匹配的 `206`。布谷来源《Snowman Pt. 3 (Sleep Soundscape) / Sia & Endel》切歌后留下 294,015 字节片段并停止增长，回点后从该片段增长至完整 9,526,622 字节；实测仅覆盖这些具体音源和当时的网络环境。
