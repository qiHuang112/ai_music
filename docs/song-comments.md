## 交互与边界

- 播放详情页增加「歌曲热评」，使用公共主题；打开后才请求，切换平台才加载对应平台，播放和预缓存不等待评论。
- QQ 音乐与网易云音乐分开显示。通过等宽的平台切换区标明来源，评论按清爽阅读列表展示；只读，不提供登录、点赞、发评论或批量抓取。
- 热评仅在应用内读取和展示，不提供「查看原文」、跳转原站或复制链接入口。未匹配到歌曲、没有热评或读取失败时显示对应说明，并保留重试操作。
- 歌单原始平台 ID 优先；已选音源仅提供明确平台的 ID 线索，必须请求官方歌曲详情验证歌名、歌手后复用。QQ MID 转换为官方数字 songid 后获取评论，不把布谷YY内部 ID 当成平台 ID。
- 没有可信 ID 时通过官方接口搜索歌曲；歌名和版本一致、歌手集合一致、已知时长差在 12 秒内才接受。相同歌曲多专辑时优先原专辑。不拿第一首翻唱／现场／串烧的评论兜底；找不到时在应用内说明未匹配到对应歌曲，允许重试。
- QQ 身份解析优先完整 `title`，为空才回退 `songname`／`name`；这些短名称可能省略伴奏等版本。用户截图确认的“凡人百世书-BGM”原始数据中4首存在该差异，因此原平台ID同样必须用完整标题核验。
- 热评每页读取20条，滚动接近底部继续加载，也可点击底部加载按钮；追加按评论ID去重，不混入最新评论。加载更多失败时保留已读内容，底部可重试同一页；服务无更多结果、重复整页或QQ游标不前进时停止。没有热评与接口失败分别显示，不生成虚构内容。手动刷新重新确认歌曲映射并回到首屏，迟到的旧分页结果不再追加。
- 滚动时提前约一屏请求下一页（480～1200逻辑像素），并预排版一屏已有评论；正文使用普通文本配合长按选择区域，由整条列表接管滚动，不添加文字入场动画。分页按钮与加载提示保持一致的最小占位高度，追加内容不挤动已读评论。
- 热评查询遇到播放音源时长与原歌单时长冲突时，只有完整歌名/版本及歌手集合均相同且原歌单有有效时长，才优先使用原歌单时长；仍保留官方身份核验。不同歌手/版本不能借用原歌单时长。案例：《关键词》林俊杰原QQ ID105393420为210秒，酷我候选记录130秒，不应因此拒绝原曲热评。
- 保存的平台ID仅作为定位线索；详情请求失败时继续按歌名、歌手严格搜索，不直接判定整首歌没有热评。搜索仍需通过相同身份和时长核验。
- QQ与网易云各自保存已加载评论和页面阅读位置，切换平台不会串结果或重复加载首屏；当前歌曲页面关闭后不继续自动请求后续页。
- 当前页面锁定用户打开时的歌曲，后台自动切歌不会把正在阅读的热评替换成另一首。
- 按完整歌曲元数据、平台与已知 ID 分开缓存，6 小时复用热评，过期后 30 天内复用已确认映射，首屏最多100组磁盘记录。后续页按查询、页码和游标缓存于内存，最多100页，复用已有可信歌曲映射，不逐页重新搜歌。并发同页请求共享结果，写入串行原子替换；错误不缓存为“空评论”。刷新失败保留已读热评并明确标记；首屏刷新使旧后页缓存失效，并隔离刷新前迟到的响应。
- 当前磁盘缓存格式为schema 3，首屏保存hasMore与下一页游标，旧schema记录重新读取。schema 2曾用于完整标题修复；本次分页继续保持原歌曲版本身份核验。
- 单个请求 8 秒超时；打开页面最多歌曲定位和热评两个步骤，有原 ID 时可能先验证 ID。超时关闭自有 HTTP 客户端，不让后台评论请求长期占用连接。
- 不读取用户 cookies、凭据或浏览器登录态；评论请求失败不影响歌曲播放。

## 验收场景

1. 播放一首歌时打开热评，网易云/QQ 分别可读，切换不改变播放；关闭再打开复用缓存。
2. 翻唱、Live、串烧、同名不同歌手不会误用原唱评论；找不到显示应用内空态说明，并可重试。
3. 断网首次打开显示读取失败；已有缓存断网刷新保留旧热评并标记，恢复网络可重试。
4. 快速切换平台、返回页面、系统后台自动下一首时不串评论；大字/窄屏可滚动，无布局溢出。
5. 页面及失败、空态中均不出现「查看原文」、跳转原站或复制链接入口；两平台评论均在应用内查看。
6. QQ 详情或搜索同时提供短 `name` 和含版本 `title` 时，以后者核验身份；伴奏、慢摇等版本不能因短名相同而复用普通版热评。旧schema缓存会重新查询。
7. 两平台各加载至少两页，第二页是不同热评；重复条目去重，QQ传递上一页原始末条SeqNo，网易云offset每次增加20；末页停止。
8. 后页失败保留当前内容，重试同页；快速滚动不并发重复请求；切换平台保留位置；分页途中刷新不混入旧页。
9. 热评页沿用公共薄荷绿主题：歌名、歌手左对齐，平台切换等宽；评论正文突出，作者、日期和只读赞数为辅助信息，条目以留白和细线分隔。支持深色、横屏及大字；长评论完整可读、可选中文字，加载中使用结构占位，空态和重试在短屏内可滚动。
10. QQ 评论中转义的换行正常排版，不显示无内容的对象占位符；保留表情和普通反斜杠，不修改缓存的原始评论。
11. 从长评论正文连续上滑，整条评论随列表移动；慢网络追加后当前阅读位置不跳动，下一页在剩约一屏时已发起请求。验证《演员》滚动及《关键词》两平台的实际读取。

本次 UI 精修参考用户指定的 [Taste redesign](https://github.com/Leonxlnx/taste-skill/blob/main/skills/redesign-skill/SKILL.md) 与 [Impeccable](https://github.com/pbakaus/impeccable)，保持原生 Flutter、既定公共配色与分页行为，不引入网页样式依赖。
