# 搜歌单：网易云与 QQ 音乐

## 用户确认的交互（2026-09-27）

- 首页输入框左侧以音符/歌单图标点击切换搜索类型，默认歌曲，取消独立切换栏。切换仅改变输入框模式，下方首页/当前结果与布局保持；提交搜索才更新结果。原歌曲搜索及截图导入保持。
- 输入关键词混合搜索网易云和 QQ 音乐公开歌单，明确标注来源，展示封面、名称、创建者与歌曲数。同名不同平台不合并。
- 首版只查看、导入，不提供导入前试听。详情按源顺序展示曲目，默认全选，可取消。
- 主按钮“导入为新歌单”，默认沿用来源名称自动创建；另一入口“加入已有歌单”允许选择目标。导入为独立副本，不跟随原平台增删。
- 导入时显示匹配进度，复用当前歌名/真实艺人/版本匹配，有候选默认选中，低置信标“需核对”；失败项单独显示。下载遵循现有歌单下载设置。

## 失败与数据边界

- 一个来源失败不遮蔽另一来源成功结果；空结果与服务失败区分，允许重试。
- 搜索分页、曲目列表完整性必须显式处理，不能把首批曲目宣称完整歌单。不可访问/缺失曲目标记出来。
- 搜索切关键词、切模式后忽略过期搜索请求；详情匹配离页后继续，可从首页任务入口恢复；暂停不产生空歌单或半途写入。
- 保存失败保留匹配结果以便重试；已有歌单依现有稳定歌曲标识去重。
- 测试覆盖双源与单源失败、分页、曲目缺失/顺序、取消、低置信、创建与追加、原歌曲搜索回归。先用模拟服务自测，再低频真实接口与77 debug体验验证。

## 实现与自测（2026-09-27）

- 首页默认歌曲，切换只改变搜索类型并保留关键词与下方内容，提交后更新结果；混合交错展示双源结果、来源/创建者/数量，分页分别管理，单源失败可单独重试。切模式或改关键词后丢弃旧请求。
- 网易云读取完整 trackIds 后分批补齐歌曲元数据并恢复原顺序；QQ 每次请求 20 个位置，分页推进使用请求窗口，避免过滤歌曲造成错页。无法读取的数量显式提示，网络读取失败允许重新加载。
- 详情默认全选；加载后提前匹配、自动采用推荐项，低置信标“需核对”；匹配中可暂停，返回后后台继续；匹配自身不写入歌单。保存失败保留匹配，可以换候选再重试。已保存曲目标记已导入；用户主动更换候选时明确提示并更新目标本地歌单，源平台的后续修改不会自动同步。
- 新建或追加都在现有歌单写入队列中一次保存，按稳定歌曲 ID 去重；追加时目标若已删除则报错。新建成功后继续导入/重试会沿用刚创建的歌单，避免重复创建。

## 核对与导入效率反馈（2026-09-27）

- 用户指出“需核对”没有可操作入口、导入慢，要求像截图搜歌一样核对，并增加打开本地目标歌单入口。
- 详情加载后自动匹配，逐行给出默认候选；点击行在原位展开候选歌名、艺人、来源和单选标记，低置信着色并明确“点击展开候选”。可边匹配边核对，或先导入已完成部分，剩余完成后继续导入同一歌单。
- 保存只写当前已选候选，不再重新匹配；页面复用同一个匹配器的缓存及在途请求。在线元数据不执行针对OCR错字的碎片搜索，截图搜歌默认策略保持；并发数、请求间隔和源保护保持。
- 已导入后仍可展开更换，更新本地目标歌单；原有歌曲不被误删，本轮添加且未被其他来源行引用的旧匹配才替换。写入失败保留原候选和歌单。核对原候选可清除提示。
- 导入成功显示“打开歌单”，新建和加入已有歌单均跳转对应本地详情。已完成导入的行不再重复保存，其余行可继续导入同一目标。

- 最新全量358项、analyze和diff-check通过。77已保留数据安装debug8119；实机确认37首QQ详情自动匹配、部分完成即可导入、展开20个候选及单选改选、暂停保留结果。导入后更新、保存失败保护和打开目标由自动化测试覆盖，手机未写入测试歌单。
