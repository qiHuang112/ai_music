# 搜歌单：网易云与 QQ 音乐

## 先建歌单，再按相似度匹配（2026-10-05，最新纠正）

- 在线详情读取完整公开曲目信息后，提供新建/加入已有歌单，先保存选中歌曲及原顺序，然后后台匹配音源；建单不等待整单匹配、不自动下载。用户纠正的是每首歌的音源匹配，不是另找相似歌单。
- 自动选源复用原歌名、艺人、版本相似度规则，优先推荐最相似结果；无推荐但仍有候选时才取第一候选兜底，不无脑取搜索首项。匹配在建单之后继续，离页不取消；本地详情显示匹配过程及失败重试。播放/下载与后台匹配复用在途查询，实际播放成功后才记住结果；失败结果不能固定，无候选和服务失败明确提示。连续三项失败按原源顺序暂停新查询，避免网络故障仍扫全单。
- 手动选源优先于晚到的自动匹配，删除的歌曲和已销毁控制器不得写回。后台匹配仅在应用进程存活时继续，未播放成功的推荐不持久化；下次点播按相似度规则复用有效的候选缓存。
- 歌单歌曲及播放详情提供歌曲来源（实际来源），点击进入切换来源，优先复用候选缓存，支持主动刷新；列出候选歌名/歌手/专辑/来源，支持修改关键词；用户选择后固定，优先于自动来源。歌曲逻辑身份、顺序、收藏与其它歌单引用应保留。已选来源失效重新搜索，手动来源失败不悄悄替换。
- 主动下载全部时允许为未选来源的歌曲按需搜索，并使用默认下载品质。仅播放使用低品质边下边播，缓存清除不移除歌单元信息。保存失败、离页、快速切歌、乱序请求和旧数据迁移需验证。

## 搜索缓存与来源入口（2026-10-05）

- 歌单歌曲更多菜单显示“歌曲来源（布谷YY / FLAC / 局域网 / 本地 / 待匹配）”，展示实际选中音源而不是歌单来自QQ或网易云；可切来源的歌曲点击跳转原切换来源页。
- 首页歌曲搜索及切换来源共用按关键词/搜索源分开的候选缓存，跨页面和重启复用，24小时有效、有界保存；来源页提供主动刷新。只存候选元信息，不把失效的媒体直链当可播放缓存；空结果和失败不固定。保留渐进搜索及旧请求隔离。
- 试用：更多菜单来源与当前播放一致；相同搜索/进入来源页不重复网络查询，切关键词/源会独立查询，刷新强制联网，重启复用；错误/空结果能够重试。

## 失败与数据边界

- 一个来源失败不遮蔽另一来源成功结果；空结果与服务失败区分，允许重试。
- 搜索分页、曲目列表完整性必须显式处理，不能把首批曲目宣称完整歌单。不可访问/缺失曲目标记出来。
- 搜索切关键词、切模式后忽略过期搜索请求；详情匹配离页后继续，可从首页任务入口恢复；暂停不产生空歌单或半途写入。
- 保存失败保留匹配结果以便重试；已有歌单依现有稳定歌曲标识去重。
- 测试覆盖双源与单源失败、分页、曲目缺失/顺序、取消、低置信、创建与追加、原歌曲搜索回归。先用模拟服务自测，再低频真实接口与77 debug体验验证。

## 新建后的自动补齐（2026-09-27）

- 用户反馈：进入在线歌单详情点“新建歌单”后，先匹配完成的歌曲入库，后续歌曲仍提示未导入，必须再点“继续导入”。新行为：新建成功后，当前读取到的这张在线歌单剩余匹配结果自动同步到新歌单，离开详情页后仍继续；不再出现“继续导入”按钮。已匹配歌曲只保存一次，保存失败保留结果并给出可恢复的重试路径。
- 用户已确认“自动补齐本次全部歌曲”：本轮不追踪来源平台以后新增或删除的曲目，不主动删除用户本地歌曲；已有歌单“加入歌单”仍保留原有手动导入语义。
- 试用场景：匹配只完成一首时点新建，剩余匹配完成后无需操作即可出现在同一个本地歌单；离开详情仍补齐；匹配乱序和重复候选不造成重复或丢歌；保存失败后重试沿用原目标，不生成第二个歌单；暂停/重试与用户手动核对仍可用。
- 实现：新建时若仍在匹配，先创建目标歌单，等本批匹配结束后按来源顺序一次写入全部已选且有候选的歌曲。任务归控制器持有，离开详情仍继续；暂停或失败后的再次匹配会自动补齐并将晚到的早序歌曲排回来源位置。低置信候选沿用原有“需核对”标记；无法读取或没有候选的曲目仍提示，来源日后的增删不会持续同步。
- 保存失败在详情显示可重试状态，重试沿用已建目标；未建成功可再次点“新建歌单”。成功新建后不显示“继续导入”；加入已有歌单保持原手动分批操作。应用进程被系统终止后的任务恢复仍沿用既有后台匹配边界，不保证终止后继续执行。
- 开发全量393项测试通过、静态分析与差异检查无问题。新增未匹配即新建、离页后乱序完成、部分匹配自动补齐、保存失败重试、暂停后早序歌曲恢复位置回归；77 debug8130保留数据试用包已安装，实机仅核对启动与只读的歌单搜索，不在用户手机创建测试歌单。自动写入行为由自动化用例验证。

## 边识别边播放（用户补充，2026-09-27）

- 新建后，已识别到的歌曲应尽快写入目标歌单，立即在歌单列表及详情中可见、可点播；无需等整张来源歌单全部匹配。后续识别结果继续补齐，目标歌单仍按来源顺序排列，去重和失败重试规则保留。
- 从这张歌单开始播放后，后续同步成功的歌曲应加入当前实际播放队列；当前歌曲、播放位置和播放状态不被重载打断。用户切换到其它歌曲/歌单或手动停止后，不得再把旧歌单的识别结果塞入新的队列。匹配任务仍只在应用进程存活时继续。

- 实现：自动同步改为识别结果每约300毫秒合批保存，匹配结束立即补最后一批；来源位置较早的晚到结果会排回本地歌单原顺序。正在识别或待核对的目标歌单暂列首页常用歌单与缓存列表自建歌单前面，并显示已识别/已入库数；完成后恢复原有使用频率排序。当前正在播放该歌单时，新入库曲目只追加至实际音频队列，不重新加载当前歌曲，切换来源后停止追加。
