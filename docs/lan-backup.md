# 局域网按设备备份与恢复

2026-11-08 用户需求：把歌单、我的收藏、歌单信息和已下载的歌曲按设备上传到局域网；多台设备可各自上传；恢复时先选设备，再按歌单、按首勾选，歌单一首不选就不建，收藏也可逐首选。

用户确认的设计：
- 每台设备在局域网上只保留最新一份备份（再次上传覆盖）。
- 上传歌单和收藏里的歌。同一首歌有多份缓存（如先缓存 128k、后下载 320k）时，只上传播放时会用的那份（`cachedTrackPlaybackPreference`：正式下载优先于播放缓存、音质高优先），低音质副本不上传；恢复后每首只有这一份。
- 恢复时合并：收藏追加，同名歌单只追加缺的歌，否则新建；本机内容不删。
- 设备名首次自动生成（如 `Android·3F2A`），可在页面里改；内部用不变的设备 ID。

实现：
- 服务端：`tool/lan_backups.py`，挂在 Mac 常驻的 8788 服务（`lan_update_server.py`）。文件按 SHA-256 去重存 `backups/blobs/`，每台设备一份清单 `backups/devices/<id>.json`；只接受局域网私有地址；保留 2 GB 磁盘余量；无清单引用的文件 24 小时后清理。接口见提交 `51ef786`。
- App：设置 → 局域网备份与恢复（`lan_backup_page.dart`）。上传前先问服务端缺哪些文件，只传缺的；清单最后提交，服务端校验所有文件都已到位。恢复时下载并校验哈希，以原缓存身份写入缓存，再经 `LibraryUseCase.mergeBackup` 合并。
- 设备身份与服务地址保存在 `lan_backup_device.json`，默认服务地址为 `defaultUpdateUrl`。
