# 歌单音源匹配

## 当前要求（2026-10-08）

建单后为每首歌按歌名、实际歌手及版本推荐最相似音源；没有合适候选时沿用来源首项兜底并显示“需核对”，不能把搜索接口返回任意结果当作已确认同曲。截图 OCR 的 QQ 序号、坐标和行识别逻辑保持，截图错字容错与在线平台曲目信息分开处理。

设置中的来源也约束匹配：明确 FLAC 或布谷YY 时只搜索该来源，Auto 才使用备用来源。长期后台任务每次开始查询时读取当前设置，同一次查询固定该次选择；源、标题和歌手分别参与缓存键。自动源已降级时不复用该源匹配器内的旧候选缓存。控制器负责切源后的旧请求隔离和持久化缓存键。

普通自建歌单中的自动推荐同样显示“需核对”：用原平台曲目信息与已选音源本地比较，在歌曲副标题旁提供入口，点击直接打开现有切换来源列表。用户选定来源后取消提示；未匹配、身份完整一致和手动固定来源的歌曲不显示。打开或滚动歌单只读取已有元数据，不额外联网搜索。

## 匹配规则

- 比较键统一大小写、全角英数字、标点及简繁字形，展示名称不变。简繁采用 OpenCC 默认字符映射，仅保留 U+4E00..U+9FFF 范围内改变的映射；不做词组转换，不猜艺人别名，不将标题内“原唱”姓名当作实际艺人。
- 多名歌手以完整署名集合比较，`/`、`&`、`、`、`feat.` 等分隔符和署名顺序不影响身份；缺少合唱歌手仍需核对。
- 现场、DJ、混音、伴奏、翻唱、纯音乐、哼唱、钢琴、哄睡、语言等版本保留为组合标签。`Live + 伴奏` 不等于 `Live`，普通录音不等于 DJ；英文歌名 `Alive` 不被当作 Live。只有可识别版本和影视说明从核心歌名中移除，未知副标题保留。
- 核心歌名先决定是否合理匹配，艺人与版本辅助排序；完整歌名、实际艺人和版本一致优先。所有标题都缺少合理相似度时保持上游首候选，不因为某个无关标题略微多几个字就重排为推荐。
- 截图保留原有单字 OCR 容错、有限片段补搜及竞争候选核对；在线平台元数据不执行 OCR 自动高置信纠错。在线 Auto 用“完整艺人 + 完整歌名”走完整双源搜索和源健康策略，不再复用截图首平台20条召回；截图原有分阶段搜索和停止条件保留。
- 完全同核心歌名且艺人有重叠时，用户指定的伴奏等版本优先于错误版本；缺少合唱署名仍需核对。只有通用 `(Version)` 被视为中性标记，浴室/慢摇等具体说明保留。平台时长已知时，以时长接近作为同曲候选的次级排序依据，防止153秒版混入201秒版；时长不能单独证明缺少版本或署名的候选正确，截图没有时长时保持原逻辑。
- 通用音源搜索评分也加入版本约束，FLAC 等编码品质不能提升错误的 Live/DJ/伴奏版本；艺人姓名仅共享若干汉字不算同一个歌手。

字符数据来源：[OpenCC TSCharacters 固定版本](https://github.com/BYVoid/OpenCC/blob/3ac34aa439a9908dd49fa92b5174b46314787ac2/data/dictionary/TSCharacters.txt)。衍生字表及完整 Apache-2.0 许可保留在 `lib/src/data/matching_traditional_chars.dart`，约 27KB，无新增运行时依赖。

## 复现与验证范围

修改前新增 8 条正式回归由主开发执行，6 条失败：合唱顺序、Live伴奏、简繁字形、在线元数据误按OCR纠错、无合理匹配时首项回退、同名错歌手未查询备用源。旧失败证据：`build/device-check/2026-10-08-sources-comments/matching-before.log`。修复后的匹配11项、评分6项与原有截图匹配/解析器回归通过；另外补充明确来源、后台任务读取新设置、一次查询固定来源、原唱署名及通用搜索版本评分的回归。验证日志 `/tmp/ai-music-matching-stream-tests.log` 同时包含流测试的一个测试服务器写法错误，该服务器修正后流健康6项另行通过；全量及最终交付由主开发统一记录。

用户随后提供截图，确认准确对象为 QQ 歌单“凡人百世书-BGM”（创建者张天一，ID `9765682818`），7首。只读原始 QQ 响应证实4首的 `name` 丢掉 `title` 中的版本；其中《Time is Broken》实际是Dr.Phonk的“浴室氛围版”241秒，《回忆观影券》实际是伴奏172秒，Manestein是“慢摇氛围版”153秒。详情解析/持久化由控制器相关改动保留完整标题和时长。

真实修复前对照进一步发现：线上 Auto 沿用截图只按标题查20首，会把 GTR7《鸿门旋律》89秒选成其他歌手182秒，或在保留完整标题后选成DJ木南《My Love》53秒；LUCHANGSHENG《星游记进行曲》也被选成其他艺人。显式FLAC使用完整艺人+标题可以召回正确版本。对真实7曲加入双模式回归：旧实现15项中5通过/10失败，修复及加入时长用例后16项通过，与原截图/新评分回归合计58项通过。测试是固定公开元数据，不会下载音频。

证据保存在 `build/device-check/2026-10-08-sources-comments/`：`exact-qq-playlist-raw.json`、`exact-qq-song-fields.jsonl`、修复前name/full-title查询结果与探针日志、`exact-playlist-regression-before.log`、`exact-playlist-regression-after.log`。

修复后再次真实查询FLAC/Auto共14次，两种模式对7首返回一致推荐：归零126秒、GTR7鸿门89秒、Dr.Phonk浴室241秒、回忆观影券伴奏172秒、LUCHANGSHENG星游143秒、Lost Control269秒、TF Manestein153秒。5首元数据完整一致；伴奏的网易云候选仅署名IN-K，Manestein来源省略“慢摇氛围版”，两者继续显示需核对，没有凭时长宣称准确版本。Auto在Bugu前三次连接中断后仅请求FLAC，进程降级已在此真实探针观察到。证据为 `exact-playlist-fixed-results.json` 和 `exact-playlist-fixed-probe.log`；探针仅查询元数据，未下载或播放歌曲音频。

试用重点：同名不同歌手、合唱署名换序、现场伴奏、普通版与DJ版、繁体平台元数据、来源切换后的未播放歌曲。候选元信息匹配不能证明远端音频内容一定与标签相同；播放器和缓存身份检查另行负责。
